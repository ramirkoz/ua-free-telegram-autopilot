# UA FREE Telegram Autopilot v2.3.44 — власницький редакційний фільтр для широкої аудиторії

Дата: 19 листопада 2026 року. Статус на створення: кандидат до незалежних GitHub CI та Windows Portable QA. Не плутати з LIVE інсталяцією оператора.

## Причина
Оператор відхилив фактично опубліковану «ПРОДАНО!» добірку з Yanko Design:
*8 Japanese Gifts for Men She’ll Love Giving and He’ll Use Every Day*
(`article_id=106538`; Telegram-скриншот 19.11 близько 16:13).
Матеріал отримав позитивне `HUMAN_EDITORIAL_236_PASS role=creative; fit=82` і перейшов у READY 15:48:11 за київським часом ще до інсталяції 2.3.43.
Попередні source-only обмеження відсікали двозначні списки та окремі фрази «best/top gifts», але не заголовки на кшталт «8 Japanese Gifts». Після оновлення успадкований READY пройшов до Telegram. Технічна справність доставки не є редакційною прийнятністю.

## Виправлення
- Новий `telegram_autopilot/v2/editorial_owner_2344.py`, source-title/body deterministic guard:
  1. `CREATIVE_GIFT_ROUNDUP_NOT_NEWS_2344`: підбірки подарунків, включно з одноцифровими, тематичними і подарунковими гідами; не забороняє одиничний справді винахідливий продукт, який згадує подарунок.
  2. `CREATIVE_SAUCE_RANKING_NOT_NEWS_2344`: рейтинги, дегустаційні порівняння й підбірки соусів/дипів; не забороняє оригінальний споживчий винахід чи рекламну кампанію за одним словом «sauce».
  3. `CREATIVE_MEME_COMPILATION_NOT_NEWS_2344`: числові збірки, галереї та рейтинги мемів; не забороняє справжній креатив або культуру лише за словом «мем».
  4. `EDITORIAL_MUNDANE_REPAIR_NOT_NEWS_2344`: рутинні ремонти, реставрації й розбирання побутових предметів із технічною процедурою. НЕ блокує підтверджені регуляторні зміни щодо ремонту, відкликання товарів, справжні технологічні прориви, біомедичні розробки чи новини про відновлення науки як інституції.
- Єдина точка інтеграції: `editorial_source_topic_reason_2319` після визначення відкаліброваної ролі (science/creative). Вона вже викликається до платного AI і в `hard_editorial_reject` перед фактичним Telegram send, тож охоплює **успадковані READY**.
- Фільтр не змінює операторські канали, джерела, графіки, квоти, моделі, `Data` чи Telegram ledger. Жодного автоблокування «ГРОМАДИ».

## Перевірка
- Read-only SQLite replay із точного операторського знімка: `106538`, `99357`, `98745`, `103186`, `100928`, `94051` класифіковані як RED.
- Позитивні контрприклади: `104656` (FDA PearlBone, **ALLOW**), `106636` (відновлення інституції науки, **ALLOW**), `98728`, `91049`, `82844`, `89018` (одиничні винаходи/кампанії, **ALLOW**).
- Приписані regression tests `tests/test_2344_owner_reader_value.py` перевіряють прямий guard, source selection і повторну перевірку READY на publish boundary. GitHub CI та нативні Windows/Defender результати мають бути дописані після їх виконання, не вважати їх наперед пройденими.
