# Autopilot 2.2.26: hard source-fact checks and safe event-memory expansion

- **Fixes human-approved publication safety:** human approval no longer monkeypatches the global `prepublish_quality_issues` function to return no issues. Only subjective editorial preferences can be waived; hard original-source checks now always run in the actual publisher immediately before any Telegram API call, including manual `force` publication. This removes a concurrent automatic-publisher QA-bypass hazard.
- **No invented fatalities:** conservative deterministic source-claim verifier compares explicitly source-stated fatality counts with counts in the final copy. It blocks new unsupported counts written with digits or simple Ukrainian numerals; multiple counts explicitly present in an evolving source report are legitimate. This is not a claim of universal semantic fact verification.
- Existing hard minimum of two genuinely completed sentences, unsafe unsettled aerial-route veto, invented road closure, unproven group kinship, polarity and uncertainty checks remain non-overridable. Shared source-fact checks also run during AI writer QA and normal prepublish, not merely for human approval.
- **Additional event-memory family:** bounded, source-owned repeated **dated and numbered municipal council acts** (same council, act type, exact date, number, <=48h) can be grouped. A document without named issuer, ambiguous multiple acts or a real follow-up about implementation is NOT collapsed. Previous 2.2.25 conservative fatal-strike event memory remains; broad generic topic matching is not elevated to hard automatic 48h decisions.
- **Editorial clarity rescue (Content Tool parity):** adds shared reader-first newsroom contract for all three profiles. The first sentence must report a clear event and identify the main actor, each paragraph must connect facts rather than string together unrelated brands/trends/statistics, abbreviations must be explained if the original provides the explanation, and unsupported trend essays/moral conclusions are disallowed. For commercial copy, preserve one compelling confirmed mechanism; for monitoring, preserve all practical instructions and outcome.
- **Mandatory independent final copyedit for the two editorial-mode channels** on every candidate that passed the writer; monitoring retains existing risk-triggered independent edit to avoid doubling its high-volume AI usage. The final editor is instructed to rebuild a confusing draft from SOURCE, not merely polish grammar. Existing providers, monthly/daily budget limits, operator scheduling and fallback controls are unchanged; this adds one bounded AI call per accepted editorial candidate.
- Adds `test_2226_reader_first_editorial.py` to guard prompts/profile separation and independent final editorial review; no claim that prompt tests alone prove publication-quality LIVE acceptance.
- Adds `test_2226_source_fact_release.py` for factual contradictions, corrections, forced human publish QA isolation, official acts versus other authorities and new civic developments.
- All changes are in shared code, not hardcoded for any channel; operator source lists, Data, media provenance, AI models/budgets, daily spending limits, 45/30/5-minute minimum posting intervals, prior COMMITTED receipts, UNKNOWN #66297 and no-auto-replay rules remain intact.
- Separate gates: PR Ubuntu/Windows CI 4/4, Windows native launcher/GUI/Defender, main release tag and checksums, then installed operator LIVE/editorial acceptance. No laptop tests or remote control of the operator machine.
