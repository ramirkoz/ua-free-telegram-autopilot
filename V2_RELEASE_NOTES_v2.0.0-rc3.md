# UA FREE Telegram Autopilot V2 2.0.0-rc3

RC3 виправляє помилку перенесення encrypted credentials, знайдену під час реальної міграції RC2 у Windows.

## Виправлено

- `secrets.key` і `secrets.secure` більше не використовують спільний temp-файл `secrets.migration.tmp`.
- Для кожного файла credentials створюється окремий унікальний temp у цільовій Data.
- Переноситься точна зашифрована пара `secrets.key + secrets.secure` без розшифрування та без логування секретів.
- Якщо встановлення одного з двох файлів зривається, частково встановлена пара прибирається або попередня пара відновлюється.
- Збій перенесення credentials більше не відкочує вже успішно перевірену міграцію каналів, джерел, policy та history. Він повертається як окреме попередження.
- Додані regression-тести на точний перенос обох файлів та заборону неявного overwrite.
- У Windows release pipeline доданий окремий native smoke-test, який реально створює legacy `secrets.key + secrets.secure`, запускає packaged runtime і перевіряє байт-в-байт обидва перенесені файли.

## Успадковано з RC2

- Windows-safe SQLite migration через online backup API замість заміни живого файла.
- Read-only legacy import.
- Backup поточної V2 бази перед міграцією.
- `PRAGMA quick_check` до і після переносу.
- Чистий V2 runtime без історичного `rcXX` patch stack.

## Як тестувати

1. RC2 не використовувати для повторного імпорту credentials.
2. Розпакувати RC3 у нову папку.
3. Запустити `UA_FREE_Telegram_Autopilot.exe`.
4. `Міграція` → `Імпортувати стару Data` → вибрати Data робочої RC82.
5. Після повідомлення про успішний імпорт перевірити канали, джерела та вкладку AI, а вже потім запускати автопілот.
