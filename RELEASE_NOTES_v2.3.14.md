# Autopilot 2.3.14 - джерельно точні оновлення графіків

**Основа:** перший LIVE 2.3.13, 5 листопада: 3/3 workers, 3/3 collectors, один природний локальний пост із правильним фото, Telegram COMMITTED 1227. Практичне повідомлення #91375 про зміни графіка світла пройшло selection, але залишилося в QUALITY_RETRY: 500-символьна мінімальна довжина змушувала моделі переповідати велику таблицю і повторюватися, а окремі кандидати обривали речення, вигадували числа або не завершували генерацію.

## Зміни

- **Цільові межі для змін графіків:** якщо першоджерело містить багатий часами графік та явне повідомлення про зміни, writer отримує компактний обсяг **220-520 символів** замість автоматичного 500-750. Табличні джерела без двох фактичних речень залишаються відхиленими. Інші пости та канали не змінюють меж.
- **Чіткий зміст замість заповнення обсягу:** два-три завершені речення, лише підтверджені черги, години й суть зміни; повна таблиця в джерелі, без зайвого переказу. За кількох явних оновлень розрізняти останню редакцію. Заборонено вигадувати тривалість, групи або час.
- **CTRL+UA:** у source-grounded калібруванні додано відмінність між фактичною технологічною новиною та корпоративним прогнозом потужностей дата-центрів. Жодного нового числового порога й автоматичної зміни редакційних міток.
- **Не чіпає:** 45/30/5, редакційне правило двох речень, числовий Fact Guard 2.3.13, provenance медіа, dedupe, обробку Telegram UNKNOWN, операторську SQLite/Data або історичні повідомлення.

## Приймання

1. GitHub CI на Ubuntu та Windows 3.11/3.12/3.13, точкові regression 2.3.13 і 2.3.14, Windows Defender/build.
2. Після окремого встановлення перевірити природний свіжий графік в каналі ГРОМАДИ: source -> final -> опублікований Telegram, всі години без вигадок. Сама збірка **не доводить** природну публікацію.
3. Звірити нові CTRL+UA і ПРОДАНО! пости проти завершеного редакторського відбору; не змінювати темп і не робити replay старих постів.
