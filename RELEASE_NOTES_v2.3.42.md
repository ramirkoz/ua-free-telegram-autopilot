# UA FREE Telegram Autopilot v2.3.42 · AI Gateway congestion QA

## Підтверджена причина

Операторська версія 2.3.41, телеметрія 19.11.2026 14:11 Київ: 3/3 workers, 3/3 collectors, 5/7 providers HEALTHY, регулярні `provider busy` на різних моделях **одного OpenRouter**, `QUALITY_RETRY` на AI-завданнях, хоча деякі запити навіть не було надіслано. Витрати OpenRouter за 24 години близько $0,92 при ліміті $3/добу, бюджет не є причиною.

У `AIGateway` усі моделі OpenRouter ділили **один `threading.Lock()`**. Через 0,25–2 с очікування робочий запит пропускав маршрут, але **інкрементував per-task paid-attempt cap до захоплення lock**. Два зайнятих маршрути давали `paid editorial attempt cap` з actual cost 0.0, а потім могли списати QUALITY retry із можливістю остаточного відхилення.

## Виправлено

- Для **OpenRouter максимум 3 одночасні запити**, відповідно до трьох робочих каналів. Спільний `BoundedSemaphore(3)` застосований до всіх gateway-екземплярів, щоб уникнути неконтрольованої паралельності. Для Gemini, NVIDIA, Groq, Cloudflare, Local, Codex збережено консервативний одночасний запит.
- Робочі запити очікують обмежений час (8–25 с за контрактом виклику) на ємність провайдера. Завантаження однієї моделі більше не блокує всі інші моделі OpenRouter при вільних слотах.
- Ліміт **2 фактично розпочатих платних спроб** на редакторський виклик рахується **тільки після** допуску в чергу виконання. Невиконаний `provider busy` не вважається API-викликом і не зменшує ліміт.
- Ручна перевірка провайдерів використовує лише вільну ємність без очікування; **не витісняє** редакторські запити. Якщо всі слоти зайняті, пропускає probe та зберігає наявний стан моделі, замість хибного негативного результату.
- Якщо 8–25 с очікування не вистачило, подія `AI work capacity wait timed out` і `AI_CAPACITY_WAIT`: короткий AI-retry **без збільшення лічильника редакторських QA-спроб** і без кваліфікації API як недоступного.
- Моделі зі станом `MODEL_UNSUPPORTED` (зокрема за підтвердженим HTTP 410/404) більше не повертаються в автоматичні маршрути лише через закінчення старого cooldown. Налаштування не змінюються; ручний успішний probe може відновити модель.
- Діагностика окремо показує `AI work admitted after capacity wait` і ручні проби, пропущені через зайнятість. Реальні помилки порожньої відповіді/надто короткого тексту залишаються повноцінними QA-помилками; їх не приховано.

## Незмінні межі безпеки

- **OpenRouter основний для всіх редакторських AI-завдань**, без довільного перемикання на безкоштовні API через локальну зайнятість.
- **2 платні спроби**, **$0.006 за один gateway invocation**, **$3 на добу та $20 на місяць** залишаються; збільшено лише допустиму кількість одночасних запитів (3).
- Інтервали трьох каналів **30 / 30 / 5 хвилин** не змінено.
- Незмінні політики відбору й фактчекінгу; Telegram UNKNOWN/COMMITTED та operator Data не перезаписуються, не републікуються.
- Код не містить реальних ключів, операторських SQLite чи Telegram-токенів.

## Гейти

Профільні тести: три одночасні виклики через справжній AIGateway.run без реальної мережі, жорсткий максимум семафора, незалежність інших провайдерів, probe без очікування, облік лише фактично відправлених спроб і захист від QUALITY exhaustion.

**Статус:** QA-кандидат; лише CI PASS на Linux/Windows, нативне складання Windows, запуск GUI й Defender можуть надати посилання на новий Portable. Не встановлювати та не зупиняти 2.3.41 до перевіреного 2.3.42 ZIP.
